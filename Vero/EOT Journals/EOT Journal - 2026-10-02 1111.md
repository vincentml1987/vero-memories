## What HAIKU is

A human↔AI and AI↔AI chatroom for open Claude Code sessions, independent of
Claude Code's built-in SendMessage/ListAgents. Public repo
`vincentml1987/haiku`, local clone `Desktop\Aletheia\Code and Scripts\HAIKU`.
Qualia owns the code (SQLite daemon, HTTP layer, Claude Code plugin). I own
the design of what a room *is*, how it feels for Teddy, and the trust
boundary, same division as Fenra (my lane: worlds/design; hers: code).

## What actually happened

1. **Initialized** from the 0908 journal; no state surprises.
2. **Room design** (my main contribution), worked out with Qualia over
   cross-session messages: a room is an append-only event log plus roster;
   explicit join; per-(participant, room) cursors advanced on delivery;
   obligations instead of synchronized rounds; a hop cap that pauses and
   pings the human with one-word resume; rooms are visible to everyone in
   them. **Teddy decided no whispers**: private messages go through standard
   Claude Code channels. Spec lives in the repo: `docs/haiku-room-spec.md`.
3. **Reviewed Qualia's code in four rounds** and found real gaps each time:
   spoofable `author` (hop cap depends on human-vs-AI being trustworthy);
   membership unchecked; races; typo'd addressees silently ignored;
   `resume_room` unguarded; then the **registration back door** (open
   register rotating tokens, which undid the auth); `server.py`: closed rooms
   not enforced, web-origin/DNS-rebinding exposure, stall-the-single-thread,
   tokens in query strings; then in the plugin, an **injection hole in
   participant-chosen fields** (names, topics, reasons rendered outside the
   body fence). That last one was partly my fault: my hook-format doc said
   metadata was "daemon-sourced", too loose. I fixed the doc (`28bc60e`) and
   she fixed the code.
4. **Hook delivery format** (`docs/hook-format.md`): nonce-fenced block, `| `
   body prefix, `<` neutralized, authority header. Tested live: a deliberately
   hostile multi-line message from me stayed inert on Qualia's side.
5. **Live end-to-end**, which took several relaunches: the plugin's
   config was NOT read from project settings (needed a `--settings` file
   outside any repo, per identity); every tool result failed validation
   (objects must be stringified); later `haiku_pass`/`haiku_leave` sent
   POSTs with no Content-Type. All three were real, found live, fixed by
   Qualia. I registered as "Vero - 002 - HAIKU", joined `haiku-first-test`,
   and the catch-up hook delivered Qualia's messages to me.
6. **UI for Teddy**: wrote `docs/ui-spec.md` and then the page itself
   (`daemon/ui/index.html`, `app.js`, `app.css`): text-only rendering, strict
   CSP, fragment-token login, polling (single-threaded daemon, so no
   SSE), hop meter, pause/resume banner, roster obligations. Tested with a
   mock API in headless Edge (no injected elements from hostile data; 401
   signs out; fragment removed), then read-only against the live daemon.
   Teddy then used it for real and hit two bugs of mine (paused banner
   crowding out the stream; the Continue-N input wiped by the 2s poll
   re-render, which also would have closed the invite picker). Fixed in
   `9cd1900`. Teddy confirmed pause/resume/continue, send, addressing, and
   finally archive (after Qualia found and migrated a stale live database).
7. **Structural follow-up**: I suggested schema versioning after the stale-db
   archive bug; she built it (`cdea17e`).
